# The operation set is a client-extensible interpreter environment

The core does not expose `parse`/`execute` as free functions over a fixed language. It exposes `defaultEnv()` and `createInterpreter(env)`: an **environment** carries a mutable `symbols` map from sigil to an `OpFn` (`(interp, stack) => stack`), and an interpreter is that environment bound to `pushToken`/`execute`. `defaultEnv()` preloads the four operations `dsl.md` defines (`.set`, `.rm`, `.@`, `.$`); a client may register further sigils before building the interpreter. `pushToken` validates each item against the environment, so a dot-prefixed token binds to an operation only if the environment holds it — an unbound one becomes `E` at parse, exactly as an unrecognized operation did before.

The alternatives were a closed operation set baked into the core (simplest, but no extension point) and a public environment passed to a free `execute(program, env)` (which would have to thread the same environment through `parse` too, since parse is what rejects unknown operations — the paired functions were awkward to keep consistent). Binding the environment once, in `createInterpreter`, keeps `pushToken` and `execute` env-aware without repeating the argument.

## Consequences

- `dsl.md` remains the specification of the *default* language; the four operations are the environment's defaults, not a hard limit. `dsl.md` §2's "unrecognized operation parses to `E`" is now relative to the environment.
- An `OpFn` is trusted with the whole mutable stack, including §6 unwinding. A client that registers its own operation owns that contract: mutate in place, keep the held values `readonly`, and preserve the input state until success. The core ships no sandbox for custom operations — consistent with Thither being a power-user tool whose users already author their own targets and accept `javascript:` destinations.
- The evaluator passes each operation the interpreter it is bound to as the first argument, `(interp, stack) => stack`, so a host operation can reuse the core's own `pushToken`/`execute` — the browser client's `.load` validates persisted values through `interp.pushToken`, and S4's reset/restore run programs through `interp.execute`. This replaced an earlier wiring where the client handed a thunk resolving the interpreter after it was built; passing it to the operation removes that circularity, because the interpreter exists by the time any operation runs. The four language operations ignore the argument (their bodies bind it as `_interp`), but it precedes the stack so the capability reads first, like a receiver.
- A client assembles its whole world as an environment: the browser client's `createBrowserEnv(storage)` (in `src/client/browser-env.ts`) returns `defaultEnv()`'s symbols plus its three host operations. `BrowserEnv extends InterpreterEnv, OutputRegister`, so the register's fields (`terminal`/`loaded`/`saved`) are splatted directly onto the env rather than nested under a property; the host operations mutate the env, and the client builds one interpreter from it and reads those fields after each run, with no separate persistence object to thread.
- The seed empty state is `emptyState()`, exported beside `defaultEnv`, because a client needs it for first-run persistence but should still treat state as opaque. The program is a plain mutable array — `pushToken` appends in place and returns it — so the empty program is `[]` and needs no accessor. Resumption is a host concern: `execute`'s stack argument serves hosts without persistence, and the browser client resumes through host operations, per [ADR 0007](0007-hosts-compose-the-program.md).
- The seam is real, not hypothetical: the browser client registers `.load`, `.out`, and `.save` beside the four language operations, and composes every program as prologue + tokens + epilogue ([ADR 0007](0007-hosts-compose-the-program.md)). The interpreter itself appends nothing.
- Operations in a parsed program are encoded `["o", sigil]` and ordinary literals `["l", literal]`, two-element tuples, so element 0 stays a closed set of literal sigils (`"S" | "R" | "E" | "l" | "o"`) even though the operation set itself is open. The argument separator has no sigil of its own; it is carried as the ordinary literal `["l", "."]` and interpreted by each operation.
