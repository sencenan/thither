# The operation set is a client-extensible interpreter environment

The core does not expose `parse`/`execute`/`emptyProgram`/`initialStack` as free functions over a fixed language. It exposes `defaultEnv()` and `createInterpreter(env)`: an **environment** carries a mutable `symbols` map from sigil to an `OperationFn` (`(stack) => stack`), and an interpreter is that environment bound to `append`/`execute`. `defaultEnv()` preloads the four operations `dsl.md` defines (`.set`, `.rm`, `.@`, `.$`) and the seed `initialStack`; a client may register further sigils before building the interpreter. `append` validates each item against the environment, so a dot-prefixed token binds to an operation only if the environment holds it — an unbound one becomes `E` at parse, exactly as an unrecognized operation did before.

The alternatives were a closed operation set baked into the core (simplest, but no extension point) and a public environment passed to a free `execute(program, env)` (which would have to thread the same environment through `parse` too, since parse is what rejects unknown operations — the paired functions were awkward to keep consistent). Binding the environment once, in `createInterpreter`, keeps `append` and `execute` env-aware without repeating the argument.

## Consequences

- `dsl.md` remains the specification of the *default* language; the four operations are the environment's defaults, not a hard limit. `dsl.md` §2's "unrecognized operation parses to `E`" is now relative to the environment.
- An `OperationFn` is trusted with the whole mutable stack, including §6 unwinding. A client that registers its own operation owns that contract: mutate in place, keep the held values `readonly`, and preserve the input state until success. The core ships no sandbox for custom operations — consistent with Thither being a power-user tool whose users already author their own targets and accept `javascript:` destinations.
- The seed empty state moved from a free `initialStack()` onto the interpreter (`interp.initialStack`), because a client needs it for first-run persistence but should still treat state as opaque. `execute` makes its own empty *working* stack internally, so there is no `initialStack()` call from outside.
- Operations in a parsed program are encoded `["op", sigil]`, a two-element tuple, so element 0 stays a closed set of literal sigils (`"S" | "R" | "E" | "lit" | "." | "op"`) even though the operation set itself is open.
